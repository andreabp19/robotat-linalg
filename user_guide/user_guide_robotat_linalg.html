Robotat Linalg Overview and Configuration

Constants to adjust the behavior and matrix dimension scope of the libraries, and a custom struct for reporting specific errors that could happen during the execution of a routine.

1. Configuration constants

MAX_VEC_SIZE

Maximum number of elements for vectors. Set by default to 10 in order to keep problems small and dense. Warning: All libraries were validated on values within this range so it's highly recommended to keep it that way, but in case you do increase the dimension limit, take into consideration that no operation is validated for vectors and matrices of dimensiones 11 and beyond and no proper functioning can be guaranteed as it's beyond the current scope of this project.

MAX_MAT_SIZE

Maximum number of elements for matrices. Set by default to MAX_VEC_SIZE * MAX_VEC_SIZE so it aligns with the size limit for vectors. That is, by default is set to 100 elements, which corresponds to 10x10 matrices at most. As with MAX_VEC_SIZE, it can be increased to accomodate for larger matrices, but bear in mind that's beyond the current validation scope of the project, and thus, would require additional numerical validation to ensure proper results.

MAX_ITERATION_COUNT_SVD

Number of iterations to be used in the jacobi method for computing the Singular Value Decomposition (SVD) of a matrix (routine matf32 jacobi svd). The algorithm implemented for the SVD uses a definite number of iterations, as opposed to a precision threshold in the result to determine when to stop because, depending on the problem, it could take a long time to reach a specified precision, leading to execution issues in the microcontrollers. On the other hand, more iteration increase execution time of the routine, so adjust as you see fit for your specific application and precision needs.

MAX_ITERATION_COUNT_SQP

Number of iterations to be used in the active-set method of the quadratic solver (routine quadprog sqp). Set by default to 30 iterations, can be increased if necessary, but most problems during testing solved in less than 10 iterations and the algorithm exits on it's own from the iteration loop once a precision threshold is achieved, so this constant won't affect in most cases (it's mostly a preventive measure in case the algorithm can't solve a problem for some reason, so it's not stuck in an unending loop).

MATH_MATRIX_CHECK

The existence of this constant allows to check for matrix sizes where the corresponding macros are used. Comment this constant to ignore matrix checks defined this way.

MATH_EQUAL_PRECISION

A float value set by default to 1E-05 to check for numerical precision in the results. This means that a result will be considered equal to, or correct, with respect to another value if both results have at least five decimal places in common. Note: in the case of matrices, this is evaluated element by element, that is, if a single element has less than five decimals of precision with respect to another matrix, both matrices will be considered different.

ILL_CONDITIONING_THRESHOLD

A float value to determine the threshold for using the Singular Value Decomposition in the linsolve routine for the linear solver. By default, it's set to 100, but the appropiate value will depend on the specific system to solve given that all numerical methods tend to accumulate some numerical error. That is, try it yourself and check how much precision do you need, set the threshold to the condition number you consider appropiate to use the SVD on.

2. Status and error struct: err_status_t

The custom struct err_status_t allows to signal the success or error a numerical operation. This struct is defined inside of matf32, though it's use throughout all the Robotat libraries as a function return type, including for some control and robotics routines. Below is an example of how to initialize an instance of err_status_t and how to print its value on the terminal: 

err status t status;              // Declaration of err_status_t instance
status = matf32 cholesky(&A, &L); // Obtain status of the routine's execution
err_status_print(status);         // Print status

The meaning of the each status message is detailed in the sections below, along with the aspects to check in the code in each case.

MATH_SUCCESS

Indicates that an operation was executed correctly and without error. It's used by the routines with type err status t across all libraries in this project.

MATH_ARGUMENT_ERROR

This error indicates that an input matrix is incorrect, whether due to its dimensiones, shape or content (such as introducing a non symmetric matrix when a symmetric one was expected). To know the exact problem, always check the arguments and documentation of the routine, as well as the characteristics of the input matrix that was used.

MATH_LENGTH_ERROR

Signals an error in the length of a matrix of vector, contrary to what was expected in a certain operation. To know the exact problem, check the dimensions of the matrices.

MATH_SIZE_MISMATCH

This error indicates that the dimensions of different matrices don't match as expected, for example, as needed for factorizations or in LTI systems where a specific relationship in the dimensions of the matrices is expected for proper multiplication. If this error arises, then it's necessary to check again the matrix dimensions.

MATH_NANINF

This error indicates that values such as NaN or Inf were detected in the result, which are problematic and unwanted. That means that something went wrong during the operation and, most probably, has to do with the input values that were used.

MATH_SINGULAR

This error indicates that a matrix is very close to, or definitely, singular. That means it cannot be inverted and that operations such as those in the quadratic solver methods will have some trouble with the precision and result of the solution.

MATH_TEST_FAILURE

This error indicates that a test case failed. It's currently not implemented as it's mostly used for diagnostic tests.

DECOMPOSITION_FAILURE

This error indicates that a matrix factorization/decomposition failed to be generated correctly, and either the algorithm itself failed or the process had to be interrupted.
