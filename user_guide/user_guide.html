Getting started with Robotat Linalg

Brief introduction to Robotat Linalg and how to use it.

Introduction: What is Robotat Linalg?

Single-precision devices with low memory capacity generally have no native support for complex algorithms such as control and robotics. Robotat Linalg provides the numerical infrastructure to cover this gap, allowing to perform onboard linear algebra, control, and robotics routines. Robotat linalg's key features are:

  • Single-precision arithmetic (float32)
  • Static memory allocation
  • No external libraries or dependencies, only the C Standard Library
These characteristics turn Robotat Linalg into a practical tool for embedded control and robotics, as it allows greater control over memory resources, while keeping all routines tailored for single-precision devices, such as Arduino, ESP32 and STM32 boards. Regarding potential applications, Robotat Linalg is currently divided across several libraries, covering different algorithms:
  • Robotat Linalg
    • Matf32: Linear algebra, matrix operations and factorizations.
    • Linsolve: Linear solver, using direct methods such as LU, QR, Cholesky and SVD.
    • Quadprog: Convex quadratic solver, using linsolve, an active set method and KKT direct methods.
  • Robotat Control: PID controller, LTI and nonlinear systems, Kalman filter, LTI shooting-based MPC.
  • Robotat Robotics: homogeneous transformations,
These libraries already cover the essentials for a variety of control and robotics applications. Additionally, it's portable across different devices and environments.

Installing in PlatformIO projects

External libraries must be included in the platformio.ini file in PlatformIO projects, using the lib_deps command. To include Robotat Linalg, add the HTTPS direction, as provided in the Github Repository: 

lib_deps = https://github.com/andreabp19/robotat-linalg.git
If you have more than one library in lib_deps, such as for sensors or any other library, separate them in different lines: 
lib_deps =  some-other-library
            https://github.com/andreabp19/robotat-linalg.git

Importing the Robotat libraries

The libraries are modular and are built like a stack. That means, the base layer is Matf32. Linsolve builds directly on top of it, and then Quadprog builds on top of Linsolve. Those three libraries form the Robotat Linalg core, in other words, the numerical infrastructure of the stack. Robotat Control and Robotics are both part of the application layer, and depending on the algorithm to use, might need one or more of the Robotat Linalg core libraries. The dependencies are handled internally, meaning that if you include Quadprog, both Matf32 and Linsolve will be included as well, and similar for the control and robotics libraries. Include the library you need according to their respective file names: 

#include "matf32.h" 
#include "linsolve.h"         // Includes both matf32 and linsolve
#include "quadprog.h"         // Includes matf32, linsolve and quadprog
#include "robotat_linalg.h"   // Includes matf32, linsolve and quadprog
#include "robotat_control.h"  // Includes robotat_linalg
#include "robotat_linalg.h"   // Includes matf32

Supported platforms

Robotat Linalg is targeted towards single-precision architecture embedded devices. As of late 2026, it has been tested in ESP32, STM32 Nucleo, and Arduino Mega development boards, and was partially tested in Tiva C. The library stack is portable and can be adapted for other devices, as long as they have enough RAM to contain the libraries and execute the routines. Performance speed will vary depending on the capabilities of the device.
